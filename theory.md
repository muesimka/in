# Часть 1. Теоретический анализ

## 1. Определение первичного ключа

**Первичный ключ исходной таблицы:** составной ключ `(student_id, subject_id)`.

### Обоснование

- Одна строка таблицы соответствует результату экзамена/тестирования конкретного студента по конкретному предмету.
- В исходных данных комбинация `student_id + subject_id` уникальна (Петров П. имеет две записи — по математике и информатике).
- `exam_date` не включаем в ключ, так как в контексте задачи предполагается один результат на студента по предмету (дата — атрибут результата).

### Почему другие варианты не подходят

| Кандидат | Почему не подходит |
|----------|--------------------|
| `student_id` | Не уникален: один студент может иметь несколько оценок по разным предметам. |
| `subject_id` | Не уникален: один предмет сдают многие студенты. |
| `teacher_id` | Не уникален: один преподаватель может принимать экзамены у многих студентов. |
| `group_id` | Не уникален: в группе много студентов. |
| `exam_date` | Не уникален: в один день могут проходить несколько экзаменов. |
| `student_id + exam_date` | Теоретически возможно, но в данных один студент может сдавать разные предметы в разные дни; надёжнее привязка к предмету. |

## 2. Функциональные зависимости (ФЗ)

Выписаны все существенные ФЗ, которые выполняются на данных:

```
student_id      → student_name
student_id      → group_id
group_id        → group_name
teacher_id      → teacher_name
subject_id      → subject_name
subject_id      → teacher_id          # в данных каждый предмет ведёт один преподаватель
(student_id, subject_id) → exam_date
(student_id, subject_id) → grade
(student_id, subject_id) → teacher_id  # транзитивно через subject_id
```

Дополнительно (транзитивные):

```
student_id → group_name          # через group_id
subject_id → teacher_name        # через teacher_id
```

## 3. Транзитивные зависимости

Транзитивные зависимости (неключевой атрибут зависит от другого неключевого):

1. `student_id → group_id → group_name`  
   ⇒ `student_id → group_name` (транзитивно)

2. `subject_id → teacher_id → teacher_name`  
   ⇒ `subject_id → teacher_name` (транзитивно)

Эти зависимости нарушают **3НФ**.

## 4. К какой нормальной форме относится таблица сейчас?

**Текущая форма: 1НФ (и даже не 2НФ).**

### Почему не 2НФ

Первичный ключ составной `(student_id, subject_id)`.  
Существуют **частичные зависимости**:

- `student_name` и `group_id` зависят **только** от `student_id` (части ключа);
- `subject_name` и `teacher_id` зависят **только** от `subject_id` (части ключа).

Следовательно, таблица **не находится во 2НФ**.

### Почему не 3НФ

Даже если бы мы устранили частичные зависимости, остались бы транзитивные зависимости (`group_name` зависит от `group_id`, `teacher_name` — от `teacher_id`).
